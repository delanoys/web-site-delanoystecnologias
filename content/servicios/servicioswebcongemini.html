🔗 Protocolo HTTP APIs RESTful Patrón MVC Práctica

🔗 1. Protocolo HTTP y Ciclo Request-Response

HTTP (Hypertext Transfer Protocol) es el lenguaje que usan los clientes y servidores para comunicarse en la web. Es la base de cualquier servicio web.

Request (Solicitud)

El cliente (navegador, aplicación) envía una solicitud al servidor. Consta de tres partes clave: el **Verbo HTTP** (GET, POST, etc.), el **Path (URL)** y los **Headers** (metadatos).

Response (Respuesta)

El servidor devuelve una respuesta que incluye: un **Código de Estado** (indicando si la solicitud fue exitosa o falló), los **Headers** y el **Body** (cuerpo, que a menudo contiene datos en formato JSON o el propio HTML).

Verbos HTTP Esenciales (CRUD)

Estos verbos se mapean a las operaciones básicas de **CRUD** (Crear, Leer, Actualizar, Eliminar) sobre un recurso:

🟢 **GET (READ):** Solicita la representación de un recurso. Es **seguro** e **idempotente**.

🟡 **POST (CREATE):** Envía datos para crear un **nuevo** recurso en el servidor. No es idempotente.

🟠 **PUT (UPDATE):** Actualiza *completamente* un recurso existente. Es idempotente.

🔴 **DELETE (DELETE):** Elimina un recurso específico. Es idempotente.

2. Desarrollo de APIs RESTful 💻

**REST (Representational State Transfer)** es un estilo arquitectónico que dicta cómo deben diseñarse los servicios web para ser escalables y simples. Usa JSON como su formato de datos principal.

Recursos y Endpoints

En REST, todo es un **recurso**. Estos recursos se identifican mediante URLs (endpoints) que siempre deben ser **sustantivos** y en **plural**.

**Ejemplo:** Para gestionar usuarios, el endpoint es `/api/usuarios` (no `/api/obtenerUsuarios`).

Códigos de Estado

El código de estado es la forma más rápida de decirle al cliente qué pasó con su solicitud.

  • **200 OK:** Éxito general (para GET, PUT, DELETE).
  • **201 Created:** Éxito en la creación (para POST).
  • **400 Bad Request:** Error del cliente (datos incorrectos).
  • **404 Not Found:** El recurso solicitado no existe.

Ejemplo de Interacción REST


// 1. Crear un nuevo producto
POST /api/productos
Body: { "nombre": "Teclado", "precio": 50 }
Respuesta: 201 Created

// 2. Obtener la lista de productos
GET /api/productos
Respuesta: 200 OK, Body: [ {...}, {...} ] (JSON Array)

// 3. Eliminar el producto con ID 10
DELETE /api/productos/10
Respuesta: 204 No Content

3. Patrón de Diseño: Model-View-Controller (MVC)

MVC es un patrón arquitectónico clave en ASP.NET Core. Ayuda a separar las preocupaciones de la aplicación en tres partes interconectadas, mejorando la organización y mantenibilidad del código.

[Image of the Model-View-Controller architectural pattern showing the flow of request from Controller to Model to View]

C: Controller (Controlador)

Es el **receptor**. Recibe la solicitud HTTP del cliente, decide qué hacer y elige la respuesta. Es el intermediario entre la View y el Model.

En ASP.NET Core, son las clases que contienen los métodos de acción (ej. [HttpGet]).

M: Model (Modelo)

Es el **manipulador de datos**. Contiene la lógica de negocio, las clases de datos (entidades) y se encarga de interactuar con la base de datos (Ej. Entity Framework Core).

Clases C# que representan la estructura de la data (DTOs) o las entidades de la DB.

V: View (Vista)

Es el **presentador**. Genera la interfaz de usuario final. En APIs REST (API Controllers), la Vista es la **serialización JSON/XML** de los datos del Modelo. En MVC tradicional, es la generación de **HTML**.

Archivos `.cshtml` para HTML o métodos que devuelven IActionResult para JSON.

Práctica Interactiva: Mapeo de Acciones REST 💪

Determina la combinación correcta de Verbo HTTP y Código de Estado para cada operación, basándote en los estándares RESTful.

📝 Desafío de Mapeo REST [HTTP_MAPPING]

Elige el **Verbo HTTP** y el **Código de Estado** más apropiados para las siguientes acciones en el endpoint /api/clientes:

  1. Eliminar el cliente con ID 5.
  2. Crear un nuevo cliente.
  3. Actualizar solo el campo "email" del cliente 10.
  4. Solicitar el listado completo de clientes.

✅ Solución y Razonamiento

  • 1. **Eliminar Cliente:** **DELETE** (`/api/clientes/5`) y **204 No Content**.
  • 2. **Crear Cliente:** **POST** (`/api/clientes`) y **201 Created**.
  • 3. **Actualizar email:** **PATCH** (Más específico para actualizaciones parciales, aunque PUT también es válido si se envía solo el campo a actualizar) y **200 OK**.
  • 4. **Solicitar Listado:** **GET** (`/api/clientes`) y **200 OK**.

**Nota de PATCH:** Si bien PUT es para reemplazo total, **PATCH** (`Microsoft.AspNetCore.JsonPatch`) se usa en APIs modernas para operaciones de actualización parcial, siendo la opción más precisa aquí. Ambos devuelven 200 OK.
