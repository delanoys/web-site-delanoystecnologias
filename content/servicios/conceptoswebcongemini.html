Conceptos Web: Marcado vs. Serialización de Datos ⚖️

Una exploración completa de **HTML/XML** (Formato) y **YAML/JSON** (Datos), sus usos y su rol en la arquitectura moderna.

⚖️ Introducción 🏷️ Marcado (HTML/XML) 💾 Datos (YAML/JSON) Práctica Interactiva

⚖️ Introducción: La Dualidad de la Web

Los lenguajes se dividen según su propósito: **presentación visual** (para el humano) o **transmisión estructurada de información** (para la máquina).

Grupo A: Marcado (HTML/XML)

Se centran en el **Contenido y Formato**. Definen *cómo* se ve la información. Usan **etiquetas** y son cruciales para el **Frontend** y la documentación. Piensa en ellos como la **estructura de un edificio**.

Grupo B: Serialización (YAML/JSON)

Se centran en la **Data y Configuración**. Definen *qué* es la información y su estructura jerárquica. Esencial para **APIs**, **Backend** y **DevOps**. Piensa en ellos como el **plano arquitectónico y la lista de materiales**.

Analogía: Idiomas para Humanos vs. Idiomas para Máquinas

La web necesita dos "idiomas" distintos para funcionar:

  • **Lenguajes de Marcado (HTML):** Hablan al **navegador**. Le dicen: "Muestra este texto como un título, coloca esta imagen aquí, y haz de este texto un enlace". Está optimizado para la **lectura y presentación humana**.
  • **Lenguajes de Datos (JSON):** Hablan al **servidor y los programas**. Le dicen: "El usuario 123 tiene un saldo de 50.00". Está optimizado para la **eficiencia y el procesamiento de datos por máquinas**.

**Clave:** Un programa (como tu API en ASP.NET Core) consume **JSON** y produce **HTML** (o más JSON para un framework moderno) para que el humano pueda verlo.

🏷️ HTML y XML: Estructura de Etiquetas

Entendiendo la jerarquía de etiquetas y sus diferencias.

HTML: Presentación Fija

Utiliza etiquetas **predefinidas** por el navegador. Su propósito es renderizar visualmente el hipertexto (texto, imágenes, enlaces).

<h1>Título de la Página</h1>

XML: Datos Extensibles

Permite crear **etiquetas personalizadas** (`eXtensible`). Su objetivo es describir la data de forma estructurada para el intercambio entre sistemas, no para la visualización directa.

<persona><nombre>Ana</nombre></persona>

💾 YAML y JSON: Serialización de Datos

El estándar de facto para la comunicación entre sistemas y la configuración de infraestructuras.

JSON: APIs y Objetos

Sintaxis basada en objetos de JavaScript. Usa **llaves `{}`** para objetos y **corchetes `[]`** para listas. Es el más común para APIs REST.

"id": 1, "status": "activo"

YAML: Configuración y Legibilidad

Diseñado para ser altamente legible por humanos. Utiliza **indentación** y el guion `-` para listas. Dominante en configuraciones de Docker y Kubernetes.

- nombre: api-1\n  puerto: 80

Práctica Interactiva y Desafío de Conversión 💪

El reto consiste en convertir un formato de marcado a un formato de datos para comprender la diferencia en estructura y propósito.

📝 Desafío de Conversión de XML a JSON [CONV_1]

Convierte la estructura de datos representada en XML al formato JSON, manteniendo la estructura jerárquica:


<inventario>
    <producto id="P001">
        <nombre>Teclado Mecánico</nombre>
        <stock>50</stock>
    </producto>
</inventario>

✅ Solución en JSON


{
  "inventario": {
    "producto": {
      "id": "P001",
      "nombre": "Teclado Mecánico",
      "stock": 50
    }
  }
}

**Explicación:** El elemento raíz (``) y el elemento hijo (``) se convierten en objetos JSON (llaves `{}`). El atributo `id` se convierte en un par clave-valor, al igual que los elementos de datos internos (``, ``).
